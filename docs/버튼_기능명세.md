# 버튼 기능 명세

> 이 명세는 현재 코드에 연결된 동작과 아직 필요한 동작을 구분합니다. 버튼의 이름만 있고 클릭 동작이 연결되지 않았다면 미완료로 표시합니다.

## 홈 화면

### 편집 / 완료

- 위치: 바로가기 카드의 웹사이트 영역 우측 위
- 현재 동작: `편집`을 누르면 내부 값 `isEditing`이 켜지고 버튼 글자가 `완료`로 바뀝니다. 반대로 한 번 더 누르면 꺼지고 `편집`으로 돌아옵니다.
- 편집 상태에서 현재 보이는 변화: 웹 링크 추가 버튼 자리 표시
- 아직 필요한 동작: 실제 링크 타일의 점 세 개 메뉴, 수정·삭제, 삭제 확인 창. 편집을 끝냈을 때 링크 변경 사항 저장 여부도 결정해야 합니다.

### 웹사이트 추가 (+ 자리)

- 위치: 웹사이트 타일 목록 안의 추가 타일
- 현재 동작: 누르면 `AddLinkWindow`를 모달 창으로 엽니다.
- 아직 필요한 동작: 타일 모양, 부모 창 중앙 배치, 이름·URL 검사, 아이콘 이미지 선택, 저장 후 홈 목록 반영.

## 바로가기 추가 창

### 이름 입력

- 목적: 타일 아래에 보여줄 바로가기 이름을 입력합니다.
- 필수 여부: 비어 있으면 안 되는 것으로 예정. 유효성 검사는 아직 없음.

### URL 입력

- 목적: 열 웹 주소를 입력합니다.
- 필수 여부: 비어 있으면 안 되는 것으로 예정. 올바른 주소인지 확인하는 동작은 아직 없음.

### 이미지 선택

- 현재 상태: 버튼 UI만 있고 클릭 동작이 연결되지 않았습니다.
- 예정 동작: 파일 선택 창에서 이미지 파일을 고르고 미리보기와 파일명을 보여줍니다.
- 아직 결정할 점: 원본 이미지 경로가 바뀌거나 삭제되어도 앱 아이콘이 남도록 앱 데이터 폴더에 복사할지 결정합니다.

### 추가

- 현재 상태: 버튼 UI만 있고 클릭 동작이 연결되지 않았습니다.
- 예정 동작 순서:
  1. 이름과 URL이 입력되었는지 확인합니다.
  2. 누락된 값이 있으면 창을 닫지 않고 해당 입력란을 안내합니다.
  3. 입력이 유효하면 링크 정보를 홈 화면의 웹사이트 목록에 추가합니다.
  4. 저장 성공 후 추가 창을 닫습니다.
- 아직 구현되지 않은 항목: 입력 확인, 오류 안내, 목록 반영, 로컬 저장.

### 취소

- 현재 상태: 버튼 UI만 있고 클릭 동작이 연결되지 않았습니다.
- 예정 동작: 작성 중인 내용을 저장하지 않고 추가 창을 닫습니다.

## 프로그램 바로가기

- 사용자가 지정한 한 폴더 안에서 프로그램을 읽어오는 방향입니다.
- 프로그램을 앱에서 직접 추가하지 않고, 지정 폴더에 있는 실행 파일을 목록으로 보여주는 방식이 목표입니다.
- 폴더 지정 방법, 실행 파일 검색 범위, 새로 고침 시점은 아직 미정입니다.

## 이후 필요한 사용자 확인

- 링크 삭제를 누르면 “삭제하시겠습니까?” 확인 창을 띄우고, 확인했을 때만 삭제합니다.
- 링크 수정 창은 추가 창과 같은 모양을 재사용할지 결정합니다.
- 외부 웹 브라우저로 열 때 유효하지 않은 주소의 오류를 어디에 표시할지 정합니다.
- 저장은 로컬 방식으로 하며, 실제 구현 단계에서 SQLite 또는 간단한 설정 파일을 비교합니다.
